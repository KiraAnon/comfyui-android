# 更新报告：保存图片 + 三个连环 bug（2026-11-15）

## 一句话

修好了「生图后保存不到相册」，顺带挖出并修掉了 **3 个更隐蔽的 bug**——其中一个让限帧功能从上线起就没生效过，另一个是它修好之后立刻把画布搞卡死。

---

## 一、问题：保存图片没反应

**现象**：点 ComfyUI 图片上的「下载」按钮，完全没动作。

**原因**：ComfyUI 的下载是 `URL.createObjectURL(blob)` + `<a download>`。
**WebView 的 `DownloadListener` 收不到 blob 下载**，`DownloadManager` 也不认 `blob:` 协议。
所以壳里不管怎么配下载，这条路径都是死的。

**修法**：走 JS 桥。

```
页面点击 <a download>
  → 注入的 SAVE_JS 拦截（捕获阶段）
  → fetch(blob) → FileReader → dataURL
  → window.KA.saveImage(name, dataURL)      [JavascriptInterface]
  → KBridge 用 MediaStore 写入「相册/ComfyUI/」
```

关键点：

- `addJavascriptInterface(new KBridge(), "KA")` 注册桥
- **Android 10+ 写 MediaStore 不需要存储权限**（`RELATIVE_PATH = Pictures/ComfyUI`）
- 写之前 `IS_PENDING=1`、写完置 0，避免相册扫到半张图
- 文件名做过滤（去路径、替换非法字符），防止 `../`

**另外补了 `DownloadListener`**：非 blob 的下载（比如以后导出 zip）交给系统 `DownloadManager`，落到「下载/ComfyUI/」。

## 二、bug 1：打开图片再点 X，满屏乱码

**现象**：图片预览里点右上角 X，页面变成一片 PNG 原始字节（`PNG IHDR...tEXtprompt...`）。

**原因**：`shouldInterceptRequest` 拦截「主框架」请求做 JS 注入时**没判断路径**：

```java
if (request.isForMainFrame()) {
    String u = request.getUrl().toString();
    if (u.startsWith(URL)) return injectMain(u);   // ← /view?filename=xxx.png 也被拦了
}
```

导航到图片时，图片请求同样是 `isForMainFrame = true`，被当成主文档注入了 JS，浏览器于是把 PNG 当 HTML 渲染。

**修法**：**按路径白名单**，只拦真正的页面文档：

```java
String path = request.getUrl().getPath();
boolean isDoc = (path == null || path.isEmpty() || "/".equals(path) || "/index.html".equals(path));
if (isDoc && u.startsWith(URL)) return injectMain(u);
```

`onPageFinished` 也加了同样的判断——否则图片页没有 `document.body`，注入会抛 `appendChild of null`（日志里那几条错误就是它）。

## 三、bug 2：限帧从来没生效过

**发现过程**：修好上面那个之后，日志里第一次出现 `[KA] perf applied`——这条以前**从来没打印过**。

**原因**：`PERF_JS` 有语法错误（`Uncaught SyntaxError: Unexpected token ')'`），整个脚本从头到尾没执行。括号不配对。

**影响**：之前测「限帧 33fps 只降 10% CPU」的结论**是错的**——不是限帧效果差，是根本没跑起来。

**修法**：重写 `PERF_JS`，并且加了一道工序：把 Java 里所有 `*_JS` 常量提取成 `.js` 文件，用 `node --check` 逐个验证语法。现在 5 个脚本全部通过。

---

## 四、bug 3：修好限帧之后，画布拖不动了

**现象**：上一步装完，画布完全不能平移。

**原因**：限帧代码里在跳帧分支调用了**已经被自己覆盖**的 `requestAnimationFrame`：

```js
window.requestAnimationFrame = function (cb) {
    return _raf(function (ts) {
        if (ts - lastT < GAP) {
            window.requestAnimationFrame(cb);   // ← 又套了一层
            return;
        }
        ...
    });
};
```

每跳一帧就多嵌套一层包装。拖动时手势触发几十次跳帧，函数被嵌了几十层，渲染循环停转。

> 这个 bug 之所以"隐藏了很久"，是因为 bug 2 让限帧代码**根本没执行**。修好语法之后它才第一次真正跑起来，立刻炸。

**修法**：**把限帧整个删掉**，`PERF_JS` 只保留关阴影/边框这类纯视觉优化。

理由：限帧实测收益只有 10% 上下（而且那个数据本身不可信），不值得冒破坏渲染循环的风险。真要限帧，用 ComfyUI 自带的 **设置 → Lite Graph → Maximum FPS**，由 litegraph 自己控制，不会伤到交互。

## 五、bug 4：keystore 密码丢了，签不了名

**现象**：`apksigner 失败（密码不对？）`，导致新代码装不上去。

**原因**：`build.ps1` 在没设 `$env:KATORCH_KS_PASS` 时会**随机生成密码并只打印到屏幕**。第一次编译时那个密码没存，第二次编译又生成了一个新密码，和已有 keystore 对不上。

**修法**：密码持久化到 `app\.kspass`（已加入 `.gitignore`），首次生成后写入文件，之后自动读取。

**代价**：这次为此**卸载重装了一次**（新签名无法覆盖旧包）。重装前备份了 app 数据，装完恢复了 localStorage——工作流提示词没丢。

## 八、教训

1. **Java 字符串拼 JS 极易出错**。这次三个 bug 里有两个是拼字符串造成的。以后改注入脚本，先用 `node --check` 验语法，再装机。
2. **`shouldInterceptRequest` 的 `isForMainFrame` 不等于"这是页面"**——图片、PDF、任何直接导航的资源都是主框架请求。
3. **覆盖全局函数时要小心自己也走那条路**。`window.requestAnimationFrame` 被包过之后，内部再调用它就是递归嵌套。
4. **"功能没生效"有时比"功能有 bug"更难发现**，因为它不报错、也没有反例。`perf applied` 这条日志救了这次。
